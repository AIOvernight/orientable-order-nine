# Contributing a review or correction

Specific, reproducible review is welcome. For a suspected mathematical problem, identify the statement and explain the failing inference or provide a counterexample. For an equivalent prior result, cite the exact work, version and theorem.

For a reproduction failure, supply the operating system, Lean and Python versions, failing stage, and relevant diagnostic lines. Keep personal paths and unrelated account information out of public reports.

Changes to mathematical data or Lean sources require updated integrity records and a fresh complete verification. Do not retain a historical PASS as evidence for changed proof files. Numerous generated finite-check modules encode single proof obligations; changing a leaf alone is not a substitute for checking the generating data and coverage.

Documentation corrections should preserve the stated theorem domains and the distinction between mathematical verification, novelty assessment and external review. Contribution and licensing terms will be finalized before accepting public contributions.

## Credit placement

Place personal project credit at the end of each document, after the main content and references. Do not add an opening byline or repeat the personal credit in the introduction. Always link the credited handle to the author's X/Twitter profile. Keep the chosen handle, profile link, and profile description together in the closing credit.
